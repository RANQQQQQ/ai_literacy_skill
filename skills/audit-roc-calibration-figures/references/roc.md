# ROC曲线核验规则

仅在图表已被可靠识别为ROC曲线时使用。

## 必查信息

1. 核对横纵坐标的实际定义。常见形式为横轴假阳性率或 `1-specificity`、纵轴真阳性率或 sensitivity，但必须以图中标注为准。
2. 识别对角参考线。若坐标为常见定义，该线通常代表随机分类基准；坐标定义异常或不清时不要机械套用。
3. 建立曲线颜色、线型、模型、队列、结局和时间点的对应关系。
4. 将每个AUC及其置信区间与正确对象配对，并标记读取置信度。
5. 判断结果来自训练集、内部验证集、外部验证集还是无法确定。

## 解释规则

- AUC反映区分能力，不等于准确率、敏感度、特异度、校准度或临床净获益。
- 在常见坐标定义下，曲线视觉上更接近左上角、AUC数值更高，可描述为所示数据上的区分能力数值更高；不要自动写成“显著更优”。
- 两个AUC的置信区间或数值存在差异，不足以替代适当的模型间统计比较。
- ROC曲线本身不能说明预测概率是否校准。
- 训练集的高AUC不能证明泛化能力；内部验证也不能自动证明外部有效性。
- 单凭ROC表现不能推出临床应用价值、决策获益、因果关系或模型已经可部署。

## 高风险措辞替换

- “准确率为0.82” → 若图中指标是AUC，改为“AUC为0.82”。
- “模型A显著优于模型B” → 无显著性检验时改为“模型A的AUC数值更高”。
- “泛化能力很强” → 只有明确、适当的独立外部验证及相应结果才能讨论；否则写成“当前图不能单独证明泛化能力”。
- “模型具有临床价值” → 改为“还需结合校准、临床净获益、外部验证及适用场景评估”。

## 最终核验

- 是否把AUC与正确模型、颜色和数据集配对？
- 是否把图形差异和统计显著性分开？
- 是否识别并使用了对角参考线？
- 是否在讨论泛化之前确认了数据集性质？
- 是否避免把区分能力扩展为校准、临床价值或可部署性？
